# 06 - AI 提示词管理：需求分析与设计

> 状态：P0 + AI 提炼已实现（2026-06-12），待部署验收
> 日期：2026-06-12
> 原始需求：把每天和 AI 对话的提示词总结、记录、收集起来，方便下次直接复制使用。
> 范围变更：应需求方要求，原 P2 的「AI 辅助提炼」提前实现，接入内网 MaaS 网关 deepseek-v4-pro（见 §11）。

---

## 1. 背景与痛点

日常和 AI（Claude Code、网页版 Claude/ChatGPT 等）对话时，会反复打磨出一些"好用的提示词"，但它们散落在：

- 各个工具的历史会话里，翻找成本高；
- 记事本 / 微信收藏 / 随手贴，没有结构，时间一长就找不到；
- 脑子里，下次要用只能凭记忆重写一遍，质量不稳定。

**核心诉求**：一个集中的提示词库 —— 存得进、找得到、一键复制出来就能用。

## 2. 目标与非目标

### 目标（解决什么）

1. **收集**：随手把一条好用的提示词存进系统，成本足够低（30 秒内完成）。
2. **组织**：通过分类 + 标签，让提示词可以按使用场景归档。
3. **检索**：关键词搜索 + 标签筛选，10 秒内找到目标提示词。
4. **复用**：一键复制完整内容；带占位符的模板先填变量再复制。
5. **沉淀**：记录使用次数和最近使用时间，常用的自动浮到前面。

### 非目标（第一期不做）

- ❌ 不做提示词的在线运行 / 调试（不接 LLM API 跑结果）。
- ❌ 不做浏览器插件、IDE 插件等外部采集入口（先用网页手动录入）。
- ❌ 不做团队协作编辑、评论、审批流。
- ❌ 不自动抓取 Claude Code / 网页对话历史（涉及格式解析和隐私，列入远期）。

## 3. 用户与使用场景

当前系统（Deploy Center）已有 GitLab OAuth 登录，提示词数据**默认按用户私有**。

| 场景 | 描述 | 对应功能 |
|------|------|----------|
| 随手收藏 | 刚和 AI 对完话，发现这条提示词效果很好，立刻存起来 | 快速新建（标题+内容+标签） |
| 找回复用 | 想起上周有条"代码审查"的提示词，要再用一次 | 搜索 / 标签筛选 / 最近使用排序 |
| 模板套用 | 同一条提示词只换项目名、语言等几个词 | 变量占位符 + 填充后复制 |
| 持续打磨 | 同一条提示词越改越好，想保留改动轨迹 | 编辑时自动留存历史版本（P1） |
| 周期整理 | 每周回顾，把零散记录合并、补标签、删掉过时的 | 列表批量操作（P1） |

## 5. 数据模型

沿用现有 `StoreService`（内存 Map + JSON 落盘）模式，新增两张"表"：

```ts
/** 提示词 */
interface Prompt {
  id: number
  userId: number          // 归属用户（GitLab userId）
  title: string           // 标题，必填，<= 100 字
  content: string         // 正文，必填，<= 20000 字
  category: string        // 分类（单选）
  tags: string[]          // 标签（多选，自由文本）
  note?: string           // 备注：适用场景、效果说明
  favorite: boolean       // 是否收藏置顶
  shared: boolean         // 是否共享到公共库（P1，默认 false）
  variables: string[]     // 正文中解析出的 {{变量}} 列表（P1，保存时自动提取）
  useCount: number        // 累计复制次数
  lastUsedAt: number | null
  createdAt: number
  updatedAt: number
}

/** 版本历史（P1） */
interface PromptVersion {
  id: number
  promptId: number
  content: string         // 该版本的正文快照
  savedAt: number
}
```

`StoreService` 增加：

```ts
private prompts = new Map<number, Prompt>()
private promptVersions = new Map<number, PromptVersion[]>() // promptId -> 最近 10 版
```

数据量预估：个人使用，几百到一两千条，单条平均 1~2 KB，JSON 落盘方案完全够用，不需要为此引入数据库。

## 6. API 设计

新增 NestJS 模块 `server/src/prompts/`（controller + service + module），全部走现有 JWT 守卫。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/prompts` | 当前用户全部提示词（前端自行搜索/筛选/排序） |
| POST | `/api/prompts` | 新建 |
| PUT | `/api/prompts/:id` | 更新（校验归属；P1 时同时写入版本历史） |
| DELETE | `/api/prompts/:id` | 删除 |
| POST | `/api/prompts/:id/use` | 复制成功后上报：useCount+1、刷新 lastUsedAt |
| PUT | `/api/prompts/:id/favorite` | 切换收藏 |
| GET | `/api/prompts/tags` | 当前用户的全部标签（去重，用于输入联想） |
| GET | `/api/prompts/:id/versions` | 版本历史（P1） |
| GET | `/api/prompts/export` / POST `/api/prompts/import` | 导入导出（P1） |

错误约定与现有模块一致：404（不存在）、403（不是自己的数据）、400（校验失败）。

## 7. 前端设计

新增 `src/features/prompts/`，路由 `/prompts`，侧边导航加"提示词"入口。

### 页面结构（单页 + 弹窗，与现有 ProjectsPage 风格一致）

```
┌──────────────────────────────────────────────────────┐
│ 提示词库                                  [+ 新建提示词] │
├──────────────────────────────────────────────────────┤
│ [🔍 搜索标题/内容/标签]  [分类 ▾]  [标签 ▾]  [排序: 最近使用 ▾] │
├──────────────────────────────────────────────────────┤
│ ⭐ Code Review 套话        编码 · #review #ts          │
│    "你是一位资深前端工程师，请审查以下代码…"     [复制] [编辑] │
│    已用 23 次 · 最近 昨天                              │
├──────────────────────────────────────────────────────┤
│ 周报生成模板               文档写作 · #周报             │
│    "根据以下工作记录，生成一份周报，要求…"       [复制] [编辑] │
│    已用 8 次 · 最近 3 天前                             │
└──────────────────────────────────────────────────────┘
```

- **列表项**：标题 + 分类/标签 + 正文前两行预览 + 使用统计；收藏项带 ⭐ 固定在顶部。
- **复制按钮**：直接写剪贴板（`navigator.clipboard`），成功 toast"已复制"，同时调 `/use` 上报。
- **新建/编辑弹窗**：标题、分类（下拉）、标签（可输入联想）、正文（等宽字体多行框）、备注。
- **变量填充弹窗（P1）**：正文含 `{{变量}}` 时，点复制先弹出表单逐项填值，预览最终文本后复制。
- 状态管理与请求封装沿用现有 `src/api` + `src/stores` 模式。

## 8. 交互细节约定

1. **复制即计数**：只有"复制成功"才上报 use，避免误点污染排序；上报失败不影响复制结果（静默）。
2. **删除需确认**：二次确认弹窗；P1 有版本历史后可考虑改为软删除回收站。
3. **搜索防抖** 300ms，纯前端过滤（全量数据已在内存）。
4. **标签收敛**：输入标签时联想已有标签，优先复用，避免 `review` / `Review` / `代码审查` 三套标签并存。
5. **正文展示**：列表内最多预览 2 行；点击标题展开完整内容（带语法高亮的等宽展示，提示词常含代码块）。

## 11. AI 网关接入（已实现）

接入公司内网 MaaS 网关（Anthropic 协议），用于「AI 提炼」：粘贴一段对话 → deepseek 提炼出提示词草稿 → 用户确认后入库。

### 接入参数（环境变量，docker-compose 已带默认值）

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `AI_GATEWAY_URL` | `https://10.0.147.128:8080` | 网关地址，调用路径 `/anthropic/v1/messages` |
| `AI_MODEL` | `deepseek-v4-pro` | 模型名（网关侧别名 claude-sonnet-4-6 / claude-opus-4-7） |
| `AI_KEY_SECRET` | 空（回退 `JWT_SECRET`） | API Key 加密密钥，轮换后已存 Key 需重新配置 |
| `AI_CA_FILE` | 空 | 网关自签名根 CA 证书路径；不配置则跳过 TLS 校验（内网可接受） |

### API Key 安全设计

- Key **不进环境变量、不进代码**：每个用户在「提示词」页右上角 ⚙ 自行配置，找管理员领取（`gw-sk-...`）。
- 保存前服务端先用该 Key 实测调一次网关，**通过才落盘**；失败直接报错不存。
- 存储采用 **AES-256-GCM** 加密（`server/src/prompts/crypto.util.ts`），密钥派生自 `AI_KEY_SECRET`。
- 页面永不回显明文，只回脱敏串（`gw-sk-ab****cd34`）；接口无任何返回明文 Key 的路径。

### 已实现的接口

`GET/PUT/DELETE /api/prompts/ai/config`（查状态/验证并保存 Key/删除 Key）、`POST /api/prompts/ai/refine`（对话→草稿）。

### 冒烟测试结论（2026-06-12，本机直连）

- 提示词 CRUD / 复制计数 / 收藏 / 标签联想 / 落盘恢复：全部通过；
- 网关连通性：本机可达 10.0.147.128:8080，假 Key 被网关 401 拒绝且错误信息友好（同时验证了自签名 TLS 链路）；
- 加密 roundtrip：加密→解密一致，错误密钥解密被拒绝。
