## 1. 发版：`pnpm deploy`

### 用法（本地 Windows，`E:\devops` 目录）

```
pnpm deploy
```

部署中会提示输 2 次服务器密码（scp 一次、ssh 一次）。嫌烦可配 SSH 免密钥（见第 4 节）。

### 背后做了什么（`deploy.ps1`）

脚本顶部两个变量决定部署目标：

```powershell
$Server    = 'root@10.0.157.73'
$RemoteDir = '/opt/deploy-center'
```

三步：
1. **打包**：`tar` 把源码打成 `deploy.tgz`，排除 `node_modules`、`dist`、`.git`、`.env`（**不传密钥**，服务器 `.env` 不会被覆盖）；
2. **上传**：`scp` 把包传到服务器 `/opt/deploy-center/`；
3. **重建**：`ssh` 到服务器，解压 → `docker compose up -d --build`（重新构建镜像并滚动重启容器）。

`package.json` 入口：

```json
"deploy": "powershell -ExecutionPolicy Bypass -File ./deploy.ps1"
```

> 首次部署很慢（拉 node/nginx/postgres 基础镜像 + 容器内 `pnpm install`）；之后有缓存，几十秒即可。
> ⚠️ `deploy.ps1` 必须保持 **UTF-8 带 BOM** 编码，否则 PowerShell 5.1 下中文输出乱码。

## 2. 容器日常操作（服务器）

```bash
cd /opt/deploy-center

# 状态与日志
docker compose ps                 # 看三个容器状态
docker compose logs -f server     # 跟后端日志
docker compose logs -f web        # 跟 nginx 日志

# 重启 / 停止 / 启动
docker compose restart            # 重启全部
docker compose down               # 停止并删容器（卷里数据保留）
docker compose up -d              # 重新启动（不重建镜像）
docker compose up -d --build      # 重建镜像并启动（改了代码后）
docker compose down -v            # ⚠️ 停止并删除数据卷（部署历史会丢，慎用）
```

## 3. 回滚

当前脚本未做版本归档。临时回滚思路：保留上一次的 `deploy.tgz`/源码快照，解压覆盖后重新 `up -d --build`。
如需正式回滚能力，可让 `deploy.ps1` 按时间戳归档每次的包，后续再加。

## 4. 可选增强（目前没做、不急）

- **SSH 免密钥**：本地 `ssh-keygen` + 把公钥追加到服务器 `~/.ssh/authorized_keys`，之后 `pnpm deploy` 不再输密码。
- **域名 + HTTPS**：在前置的 `ddc-nginx` 或新增反代上，把域名指到 `:8080` 并配证书。
- **接入 PostgreSQL**：把 StoreService 换成 Prisma 实现（StoreService 是唯一持久化边界，换 `useClass` 即可不动业务代码），见 [05-Prisma数据库迁移.md](05-Prisma数据库迁移.md)。

## 5. 故障排查

| 现象 | 排查 |
| --- | --- |
| 访问 8080 白屏 | `docker compose logs web`；确认 build 阶段 `vite build` 成功、dist 已拷入 |
| 登录后 502/无响应 | `docker compose logs server`；确认 server 起在 3000、nginx `proxy_pass http://server:3000` 可达 |
| 触发部署 403 | 用户对该项目的 GitLab 角色需 ≥ 环境阈值（测试 Developer=30，生产 Maintainer=40）；PAT 的 scope 需为 `api` |
| 重启后历史清空 | 数据卷被删（`down -v`）或还在用未挂卷的临时目录 → 确认 `serverdata` 卷在 |
| 拉不到项目 | 服务器到 `GITLAB_URL` 网络不通，或该账号在 GitLab 无可见项目 |
| 部署按钮置灰 | 项目默认分支无 `.gitlab-ci.yml` → 在项目卡片「配置 CI」创建后即可部署 |

## 6. 关键文件清单

| 文件 | 作用 |
|------|------|
| `deploy.ps1` | 本地一键部署脚本（打包→上传→远端重建），UTF-8 带 BOM |
| `package.json` → `scripts.deploy` | `pnpm deploy` 的入口 |
| `docker-compose.yml` | 编排 web/server/db 三容器 + 两个数据卷 |
| `Dockerfile`（根） | 构建 web 镜像（前端构建 + nginx） |
| `server/Dockerfile` | 构建 server 镜像（NestJS） |
| `nginx.conf` | web 容器的 nginx 配置（静态托管 + /api 反代 + SPA 回退） |
| 服务器 `/opt/deploy-center/.env` | 生产环境变量与密钥（**只在服务器，不随发版上传**） |
