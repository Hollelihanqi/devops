## 1. 架构总览

```
开发者本地 (Windows)                      CentOS 服务器 (10.0.157.73)
┌────────────────────┐                  ┌───────────────────────────────────────┐
│  E:\devops          │                  │  /opt/deploy-center/                   │
│                     │   pnpm deploy    │                                        │
│  deploy.ps1 ────────┼──tar+scp+ssh────▶│  docker compose up -d --build          │
│  (打包→上传→重建)    │                  │                                        │
└────────────────────┘                  │   ┌─────────┐  ┌──────────┐  ┌──────┐  │
                                         │   │  web    │─▶│  server  │─▶│  db  │  │
   浏览器 ──http://10.0.157.73:8080──────┼──▶│ (nginx) │  │ (NestJS) │  │ (PG) │  │
                                         │   └─────────┘  └──────────┘  └──────┘  │
                                         └───────────────────────────────────────┘
                                                       │
                                            后端调用内网 GitLab API
                                            http://10.0.6.203:8088
```

- **前后端同源**：浏览器只访问 `web`（8080）。`/api` 开头的请求由 web 容器里的 nginx 反向代理到 `server`，前端 API 走相对路径 `/api`，**不存在跨域（CORS）问题**。
- **后端是 BFF**（Backend for Frontend）：代理 GitLab API、持有/校验用户 Token、做权限与审计，前端从不直连 GitLab。

## 3. 三个容器分别是什么、干什么用

执行 `docker compose up -d` 后会起 **3 个容器**，定义在仓库根的 `docker-compose.yml`：

### ① `web`（自构建镜像，基于 `nginx:alpine`）
- **角色**：网站入口 + 静态托管 + 反向代理。
- **干什么**：
  1. 托管前端打包产物（`dist/`），浏览器访问的就是它；
  2. 把 `/api/...` 请求**反向代理**给 `server` 容器（配置在 `nginx.conf`）；
  3. SPA 路由回退：刷新子页面时回退到 `index.html`，避免 404。
- **端口**：对外 `8080` → 容器内 `80`（`WEB_PORT` 决定对外端口）。
- **构建**（根 `Dockerfile`，多阶段）：node 镜像里 `pnpm install` + `vite build`，再把产物塞进 nginx 镜像，最终镜像很小。

### ② `server`（自构建镜像，基于 `node:22-alpine`）
- **角色**：后端 BFF（业务大脑）。
- **干什么**：
  1. 处理前端 `/api` 请求：登录鉴权、项目/分支查询、触发部署、查进度/日志、取消等；
  2. 用用户的 GitLab Token 调内网 GitLab API，权限天然继承用户在 GitLab 的角色；
  3. 把部署记录写到 JSON 文件（挂 `serverdata` 卷，重建容器不丢）。
- **端口**：容器内 `3000`，**不对外暴露**，只在 docker 内网被 web 反代访问。
- **构建**（`server/Dockerfile`）：`nest build` 后 `node dist/main.js` 启动。

### ③ `db`（官方镜像 `postgres:16-alpine`）
- **角色**：PostgreSQL 数据库，为 JSON 存储迁移到关系库做准备。**当前业务代码仍用 JSON 文件，db 暂时是"起着备用"状态**（接入步骤见 [05-Prisma数据库迁移.md](05-Prisma数据库迁移.md)）。
- **端口**：容器内 `5432`，不对外暴露。
- **持久化**：挂 `pgdata` 卷；compose 配了 `pg_isready` 健康检查，server 等 db `healthy` 后再启动。

> 三者关系：浏览器 → **web**（8080）→（/api 反代）→ **server**（3000）→ **db**（5432）/ GitLab API。

### 数据持久化（重建容器不丢）

| 卷 | 挂到 | 存什么 |
|----|------|--------|
| `serverdata` | server 容器 `/app/data` | 部署历史等 JSON 数据（`store.json`） |
| `pgdata` | db 容器 `/var/lib/postgresql/data` | PostgreSQL 数据文件 |

只要不手动 `docker volume rm` 删卷，`docker compose down` / 重新 `up --build` / 重启服务器，数据都还在。

## 4. 一次性前置准备（在服务器做）

> 这些只做一次。之所以手动建、且部署脚本**故意不上传 `.env`**，是为了让密钥/端口只在服务器存一份，发版时不会被覆盖。

```bash
# 1) 建代码目录
mkdir -p /opt/deploy-center

# 2) 生成 JWT 密钥
openssl rand -hex 32     # 复制输出

# 3) 写生产环境变量（密钥用上一步生成的，端口已避开被占用的 80）
cat > /opt/deploy-center/.env <<'EOF'
GITLAB_URL=http://10.0.6.203:8088
JWT_SECRET=<填上面 openssl 生成的随机串>
FRONTEND_URL=http://10.0.157.73:8080
ADMIN_USERNAMES=lihanqi
DB_PASSWORD=deploy_pg_2026
WEB_PORT=8080
EOF

# 4) 确认 docker compose v2 可用
docker compose version
```

`.env` 各项含义：

| 变量 | 作用 |
|------|------|
| `GITLAB_URL` | 后端调用的 GitLab 地址（内网） |
| `JWT_SECRET` | 登录会话签名密钥，必须是随机串，**勿泄露** |
| `FRONTEND_URL` | 允许的来源（CORS）；同源部署下基本不触发 |
| `ADMIN_USERNAMES` | 平台管理员的 GitLab 用户名（逗号分隔）；**须与 GitLab `@用户名` 完全一致**，改后重启生效 |
| `DB_PASSWORD` | postgres 容器的数据库密码（仅 docker 内网用） |
| `WEB_PORT` | 网站对外端口（本机 80 被既有容器占用，故用 8080） |

> 若启用 OAuth 登录，还需补 `GITLAB_CLIENT_ID` / `GITLAB_CLIENT_SECRET` / `OAUTH_REDIRECT_URI`，见 [02-GitLab-OAuth应用配置.md](02-GitLab-OAuth应用配置.md)。当前用 PAT 登录，缺这三项只会有无害警告。

## 5. 首次上线

代码就位后（本地执行 `pnpm deploy` 上传，或手动放到 `/opt/deploy-center`）：

```bash
cd /opt/deploy-center
docker compose up -d --build      # 构建并后台启动（首次要拉基础镜像+装依赖，较慢）
docker compose ps                 # 三个容器应为 Up / healthy
docker compose logs -f server     # 看后端日志
```

访问 `http://10.0.157.73:8080` → 登录 → 进入项目列表即成功。

## 7. 首次部署实际踩坑记录（2026-06-10）

| 现象 | 原因 | 解决 |
|------|------|------|
| SSH 卡在 `Are you sure you want to continue connecting?` 无法输入 | host key 确认提示跑在 pnpm 子进程里，键盘输入传不进去 | 给 scp/ssh 加 `-o StrictHostKeyChecking=accept-new`，自动接受、不再弹框 |
| web 容器报 `Bind for 0.0.0.0:80 failed: port is already allocated` | 服务器 80 端口被既有容器 `ddc-nginx`（openresty）占用，**不可动** | 改用 8080：`.env` 设 `WEB_PORT=8080`、`FRONTEND_URL=...:8080`，再 `docker compose up -d` |
| 启动时 `GITLAB_CLIENT_ID/SECRET/OAUTH_REDIRECT_URI not set` 警告 | 登录已改为 PAT，OAuth 变量未配置 | 无害，可忽略（见 02 篇现状说明） |
| `deploy.ps1` 中文输出乱码（如 `鎵撳寘婧愮爜`） | 脚本是 UTF-8 无 BOM，Windows PowerShell 5.1 按 GBK 解析 | 脚本改存为 **UTF-8 带 BOM** |

## 8. 二期增强（非阻塞上线）

| 项 | 说明 |
| --- | --- |
| OAuth token 自动刷新 | `expiresAt` 临期用 refresh_token 续期，失败再要求重登 |
| SSE 实时推送 | 用 `/api/deployments/:id/stream` 替代前端轮询（nginx 已配 `proxy_buffering off`） |
| GitLab Webhook | 接收 Pipeline/Job 事件实时更新状态，降低轮询压力 |
| 审计日志落库 | 部署/取消/配置变更写 `AuditLog`，后台可查 |
| 项目/分组缓存 | 高频列表加 Redis 缓存（TTL 5~10 min + 手动刷新） |
| HTTPS | 生产务必启用，`FRONTEND_URL`（及 OAuth 回调）同步改 https |
| 多副本 | server 无状态化后（state/会话移到 Redis）可水平扩展 |
